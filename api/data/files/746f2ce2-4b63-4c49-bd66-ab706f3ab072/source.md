
# sam1

任务定义：Promptable Segmentation
给定任意分割提示 (prompt)，返回一个有效的分割掩码。

```
Image (1024×1024) → [Image Encoder] → Image Embedding (256×64×64)
                                              ↓
Prompt (点/框/掩码/文本) → [Prompt Encoder] → Prompt Embedding
                                              ↓
                                  [Lightweight Mask Decoder] → Masks + IoU scores
```

关于image encoder：
- **Backbone**: MAE 预训练的 ViT-H/16[^1]
- **输入**: 1024×1024，短边 padding
- **细节**: 14×14 windowed attention + 4个全局 attention block
- **输出**: 16× 下采样 → 64×64 特征图


关于Prompt Encoder：
提示分割：给定任意分割提示后输出一个掩码，提示类型可以是一个像素点、一个方框、或文本

关于点提示：前景点和背景点是交互式分割中的基本概念，用来告诉模型"我要这个"还是"我不要这个"，举个例子：
假设图片里有一只猫躺在沙发上：
场景 1：用户点击：猫身上的一个点（标记为 foreground），那么模型应该输出：整只猫的掩码
场景 2: 用户点击：猫身上的点（foreground）→ "我要这只猫"，沙发上的点（background）→ "沙发不要"，模型预期输出：只包含猫、排除沙发的更精确掩码

如何实现：
稀疏提示 (Sparse Prompts)：稀疏提示包括点、框、文本，它们都被编码为一组 256 维的 token 向量：
- `点嵌入 = 位置编码(点的坐标) + 可学习嵌入(前景或背景)`；每个点产生一个256维向量
- `框嵌入 = [ 位置编码(左上角) + "top-left"学习嵌入 , 位置编码(右下角) + "bottom-right"学习嵌入 ]`；每个框产生两个256维向量
- 文本直接过 CLIP text encoder → 输出一个·文本嵌入向量

密集提示 (Dense Prompts)：掩码：一系列计算后融入 image embedding，不产 token


关于Lightweight Mask Decoder：
两层decoder，每层分成四步：
- Tokens Self-Attention
- Token（Query) → Image（Key、Value） Cross-Attention
- Point-wise MLP(每个 Token 独立过 MLP)
- Image（Query） → Token（Key、Value） Cross-Attention


# sam2
在sam1的基础上推广到视频分割。

任务定义：PVS (Promptable Visual Segmentation)
输入: 视频 + 任意帧上的提示（点、框、掩码）  
输出: 目标对象在整个视频中的时空掩码（称为 masklet）（实质就是每一帧的掩码）

```
┌─────────────────────────────────────────────────────────────────────┐
│                         SAM 2 整体架构                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   当前帧图像        提示(点/框/掩码)        过去帧的记忆              │
│       ↓                  ↓                    ↓                     │
│  [Image Encoder]    [Prompt Encoder]     [Memory Bank]              │
│       │ 256×64×64         │                    │                    │
│       └───────────────────┴────────────────────┘                    │
│                         ↓                                           │
│                [Memory Attention] ← 关键创新：用记忆条件化当前帧特征   │
│                         ↓ 256×64×64                                 │
│                [Mask Decoder] (轻量，同SAM设计)                      │
│                         ↓                                           │
│              分割掩码 + IoU分数 + 遮挡分数                            │
│                         ↓                                           │
│                [Memory Encoder] → 存入 Memory Bank (供后续帧使用)     │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```


Image Encoder：
- **Backbone**: MAE 预训练的 Hiera（替代 SAM 的 ViT-H）
- **特点**: 层次化结构（hierarchical），可输出多尺度特征
- **输出**: 每帧的无条件特征 token（feature embeddings）

这里的`[1,576,1024]`怎么来的？
原图像是1008x1008，按照14x14的patchsize应该得到72x72=5184个patch，按理说这里的绝对位置应该有5184个才对，这里其实做了简化：Windowed Absolute = 窗口内的绝对位置
把1008x1008分成了3x3的九个窗口，每个窗口内部的patch按绝对位置编号，即576个patch，像这样同一份 pos_embed 复用到 9 个窗口。
为什么能这样设计？
- 因为大部分层 (28/32) 使用窗口注意力，每个窗口独立计算，所以只需要窗口内的绝对位置编码
- 全局层 (4/32) 则依赖 RoPE 提供跨窗口的相对位置信息
